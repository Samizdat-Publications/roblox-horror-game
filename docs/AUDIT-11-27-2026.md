## 1. Untrusted client input: PASS WITH NOTES

Evidence:

- Only RemoteEvents exist, no RemoteFunctions: `src\shared\Remotes.luau:29-43`; Net creates exactly these (`src\server\Net.luau:293-307`).
- `BoatInput`: rate limit, both args finite in -1..1, drowned players refused, book open zeroes the helm, and `BoatService.setHelmInput` refuses anyone but the helm seat (`Net.luau:175-195`, `BoatService.luau:299-307`).
- `Gaze`: rate limit, finite yaw within pi + 0.01 (`Net.luau:197-205`).
- `Intent`: rate limit, kind whitelist, num in 0..1, flag boolean, text at most 32 chars, Callout phrase from `Config.Callouts`, required fields per kind (`Net.luau:84-113, 207-228`). Hand intents refused while the book is open (`Net.luau:40-48, 217`).
- Banking distance: Net checks the boat is within `bankRadius` of the dock end from server kinematics (`Net.luau:157-164, 221`), and Core checks again with `LakeMap.canBank` on the server-observed boat position (`Core\Night.luau:484-491`). Good defense in depth.
- `Lobby`: rate limit, short string action, bounded value (`Net.luau:243-273`); LobbyService only lets the host change difficulty, mode, start or leave the end card, and Endless needs the host's unlock (`LobbyService.luau:190-218`).
- `Cosmetic`: `Validate.Cosmetic` whitelist plus `Profile.equip` unlock check (`Net.luau:278-285`, `DataService.luau:353-366`).
- Catches, quota, deaths: the client only sends intents. The fish roll, wrong flag and points are server side (`Core\Fishing.luau:157-186`); the quota only moves through `bank` (`Night.luau:484-487`); deaths come only from rule fail effects and water drag (`Night.luau:613-652, 701-723`). Dead players can only ring the ghost bell, with a cooldown (`Night.luau:422-428`, `Core\Ghost.luau:25-36`). No client path revives anyone.
- Wrong fish leak: events go through `sanitize`, which drops `wrong` and `tier` at any depth (`NightService.luau:128-150, 175`); `Fishing.publicCatch` sends only species, points and traits (`Fishing.luau:226-228`); the replicated `NightView` holds the hold as a count only (`Night.luau:1005-1043`); the finale HUD flag checks species only, never truth (`NightService.luau:237-256`). Points are the species' points, the same for a wrong fish.
- Debug remotes: created only under `RunService:IsStudio()` on the server (`Net.luau:311-325`); `Net.allowDebug` re-checks `IsStudio()` (`Net.luau:351-353`); DebugDriver is required, and its BindableFunction made, only in Studio (`Main.server.luau:104-120`); `DebugDriver.run` errors outside Studio (`DebugDriver.luau:808-810, 849-852`). The debug handlers only record acks (`DebugDriver.luau:813-838`). Unreachable in a live game.

Notes and fixes:

- **(medium) Two validators.** `Net.luau:50-151` is a local "SEAM" copy of the checks and the token bucket "until the Core modules land". The Core modules have landed (`Core\Validate.luau`, `Core\RateLimit.luau`, both with specs), but Net only uses `Validate.Cosmetic`. The shipped checks are therefore untested, and the two have already drifted: `Validate.LOBBY` (`Validate.luau:31-38`) lacks the `Book`, `Touch`, `Title` and `Hello` actions Net handles, and has `Ready`, `Supply` and `Retry` that Net never routes. Fix: in Net, call `Validate.BoatInput`, `Validate.Gaze`, `Validate.Intent` and `Validate.Lobby` and use `RateLimit` for the buckets; add `Book = "flag01"`, `Touch = "flag01"`, `Title = "none"`, `Hello = "none"` to `Validate.LOBBY` (a 0 or 1 number shape), with spec cases; then delete the seam block.
- **(low) toClient remotes accept client fires with no handler.** `View`, `Events`, `LobbyState` and `Profile` are RemoteEvents a client can `FireServer` on; with no `OnServerEvent` connected, Roblox queues the calls and then warns that the invocation queue is exhausted, which lets a client spam the server console (against the stated goal at `Net.luau:5-6`). Fix: in `Net.init`, after creating the folder, connect a no-op that counts a rejection: `for _, name in Remotes.toClient do (f:FindFirstChild(name) :: RemoteEvent).OnServerEvent:Connect(function() count(Net.stats.rejected, name) end) end`.
- **(note, inherent) Gaze and Touch are client-reported.** The Watcher reads `gazeYaw` and `touch` (`Core\entities\Watcher.luau:82-98`, `NightService.luau:306-308`). An exploiter can hold a perfect "edge of sight" yaw forever, or claim `Touch` on a PC for wider cones. No server truth exists for camera direction; accept it, or clamp gaze changes to a plausible turn rate per second.
- **(note, by design) A crewmate can grief.** `Wave` from any living player takes the waver during the Neighbor (`Neighbor.luau:236-241`) and the Finale (`Finale.luau:303-312`). It is the rule, and only the waver dies.
- **(note) Book bucket order.** A `Book` message spends the shared Lobby bucket first (`Net.luau:244-251`), so rapid book toggles can briefly delay that player's own `Start` or `Hello`. Harmless; check `action == "Book"` first and use only the Book bucket for it.

## 2. Scares inside a guaranteed quiet window: PASS WITH NOTES

Evidence:

- Every director spawn passes `realAllowed`: opening grace, `lastResolved + quietGap`, not safe, concurrency cap, budget, fake-out clearance, late cutoff (`Core\Director.luau:234-245`). Resolution starts the gap and redraws the cycle no earlier than the gap (`Director.luau:361-376`).
- Rules are paused in the dock light: their clocks stop and nothing fails (`Night.luau:654-660, 664`). Individual rules also refuse fails while safe (Hum `Hum.luau:166`, Knocking `Knocking.luau:113`, Neighbor `Neighbor.luau:234`, Watcher `Watcher.luau:148`, Finale `Finale.luau:302`); the flood does not rise in the light (`Night.luau:727`); a swimmer in the light is not "in the water" (`NightService.luau:296-299`).
- Property test: 0 violations over 2500 nights (spec output above).

Notes:

- **Overlap is by design, not a gap breach.** At high attention a second rule may start while one is active (`Director.luau:299-302`, up to `maxConcurrent`). The fast sim shows a start-to-start gap of 25.8 s on night 4 solo while `quietGap` is 30 s, which is that overlap. The sim's "Shortest real gap" column measures start to start (`tools\sim\rules.luau:155`), not resolution to start, so it reads like a violation when it is not. Fix (clarity): rename the column "Shortest start-to-start gap" or add a resolution-to-start column.
- **Wrong Catch is outside the director, by design.** It starts on banking, at the dock, inside the light, and its timer runs there (`Core\entities\WrongCatch.luau:1-14`, `Night.luau:362-366`). Its fail eats banked fish (no death) and can land inside a quiet gap or while the boat sits in the light. Documented; acceptable because nobody dies.
- **The Finale is outside the director, by design.** At 4 AM on night 5 it releases every active director rule as passed and starts (`Night.luau:855-876, 970-975`), whenever the last scare ended. Its strikes never land before `warn` (4 s scaled) or inside the light (`Finale.luau:10-11, 302`).
- `Night.debugForce` skips the gates but is Studio only and is told to the director (`Night.luau:1049-1104`, `Director.luau:380-393`).

## 3. Any scare without a learnable cue: FAIL

Evidence of the general guarantee:

- `EntityBase` holds any fail until the cue has been out `warn` seconds, scaled; a cue for one player waits at least `soloCueMinSeconds` (`Core\EntityBase.luau:5-12, 73-81, 138-198`).
- Per rule: Hum cue is the chorus cut, warn = silence + comply (`Hum.luau:39-41, 143-147`); Knocking cue is three knocks, a wrong round re-cues hard (`Knocking.luau:40, 62-75, 97-104`); Neighbor cue is the oarlock creak or the beacon (`Neighbor.luau:224-233`); Watcher cue is the figure (`Watcher.luau:133-137`); Finale cue is the bell, strikes gated by `canFail` (`Finale.luau:281-302`); Wrong Catch cue is the cooler settling, knock after `knockDelayMin..Max` (`WrongCatch.luau:30-60`). The client also builds a rising "still" warning toward the stop limit (`src\client\fx\Finale.luau:26-27, 930-940`).
- Water drag: `DragWarning` at `warnAt`, death at `dragSeconds`, both scaled (`Night.luau:701-723`).
- Same cue every time: no client fx module reads `variant` (search of `src\client\fx` and `RulesFx.luau` for "variant": no hits); variants only change the answer in Core (`Hum.luau:102`, `Knocking.luau:41`, `Neighbor.luau:258`, Watcher StareItDown).
- Rules sim contract: 8308 checks, 0 violations.

**Problem (must fix): the solo Watcher.** The first Watcher of a night is cued to one player only (`Director.luau:249-252`; `EntityBase.cue` sends `only`, `EntityBase.luau:130`), and the client builds the figure only from that `EntityCue` (`src\client\fx\Watcher.luau:198-209`; the presenter leaves `only` content to the client, `EntityPresenter.luau:3-4`). Two paths then fail someone with no cue:

- a) While the spotter is alive, the fail takes `nearest(s, obs)`, which picks the living player facing away the most from all players, not the spotter (`Watcher.luau:99-114, 195-198`). The victim may have seen nothing. DESIGN allows a solo cue if it leaves 12 s to tell the crew (`docs\DESIGN.md:122`), so this one is arguable, but it is the harshest case.
- b) If the spotter dies during the sighting (drag, or a second overlapping rule), `soloAlive` turns false and everyone's gaze counts (`Watcher.luau:152-163`), but no living player has the figure on screen and `EntityMoved` still goes only to the dead spotter (`Watcher.luau:116-123`). It keeps stepping when "nobody watches" and takes a living player who was never cued. If the spotter disconnects, Core keeps them alive with a default gaze of 0 (`Night.luau:521-535`), so the same thing happens.

The sim contract does not catch this: it checks one cue and the warn time per rule, not that the cue reached the player who was taken, and it does not check `EntityStrike` (`tools\sim\crewbot.luau:568-627`).

Fix: in `Watcher.step`, right after the cue block, end a solo sighting whose spotter is gone:

```lua
if b.only ~= nil then
	local present = false
	for _, p in obs.players do
		if p.id == b.only then present = true end
	end
	if not present or obs.alive[b.only :: PlayerId] ~= true then
		EntityBase.pass(b, events, { pos = { x = s.pos.x, z = s.pos.z }, spotterGone = true })
		return events
	end
end
```

and in the fail, take the spotter while the sighting is solo: `local who = if b.only ~= nil and obs.alive[b.only] then b.only else nearest(s, obs)`. Also make `NightService` pass `present = false` (or omit) for a departed player so Core can tell; today `playersObs` fills a seated default (`Night.luau:527-532`). Add a Rules spec: spotter dies at t = 5, assert no `EntityFail` kills anyone else. Add a crewbot contract check that every killed player received the rule's `EntityCue` (or the cue had no `only`).

Note: Finale strikes share one cue (the bell) and one 4 s warn; per-hazard timing (hazards ahead at 60 to 120 studs, kill at 45, boat up to 28 studs/s) was not checked, and `run.luau` was not run. Marked not checked.
